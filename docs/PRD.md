## 1. 제품 개요
- **이름(가칭):** ShooT (SHY 스펙상 가칭 "우리끼리 가계부 / Our Ledger") — 출처: `ShooT 하윤.dc.html` 로고, SHY 스펙 "0. 프로젝트 개요"
- **한 줄 정의:** 가족·부부·커플·룸메이트 등 원하는 단위로 그룹을 만들어 지출을 함께 관리하는 공유 가계부 — 출처: `ShooT 하윤.dc.html` 소개 문구, 01-problem.md 4요소
- **목적:** 투명성 · 신뢰성 · 정산 편의 — 출처: 01-problem.md "목적"
- **대상:** 대학생, 부부, 커플 — 출처: 01-problem.md 4요소 "대상"
- **문제:** 지출 출처를 알 수 없거나 영수증 등록이 번거로워 돈이 사라진 것처럼 느끼고, 그룹원끼리 각자 다른 방식으로 기록하거나 직접 정산해야 해 한곳에서 나눠 보기 어렵다 — 출처: 01-problem.md 4요소 "문제", 자세한 근거·불편 상세 6개는 01-problem.md 참고

## 2. 핵심 사용자 흐름
02-workflow.md의 To-Be 흐름 요약(자세한 As-Is·감정·불편은 02-workflow.md 참고):

S1 그룹 생성·참여 → S2 지출 발생 → S3 출처 확인 → S4 영수증 촬영 자동 등록 → S5 인식 실패 항목 후수정 → S6 공유 여부 정하기(자동 판단) → S7 그룹 지출 확인(피드) → S8 지출 오기입 수정·삭제 → S9 그룹 정산

- 분기1: OCR 실패 시 S5, 성공 시 S5 건너뜀
- 분기2: 그룹 미소속이면 지출은 개인 지출로만 남고 S6·S7로 이어지지 않음
- 분기3: 그룹장이 그룹을 나가면 다른 그룹원에게 그룹장 역할을 위임해야 함(05-policy.md 상태값1)
- 저금(S10)은 신규 기능으로 그룹 흐름과 독립적으로 개인 또는 그룹 단위로 등록됨

## 6. 정책 (요약 — 전체는 05-policy.md)
| P | 한 줄 |
|---|---|
| P1 | 그룹 이름 없으면 그룹 생성 불가 |
| P2 | 그룹명 변경은 OWNER만 |
| P3 | 같은 그룹에 중복 참여 불가 |
| P4 | 그룹 멤버가 아니면 그 그룹으로 지출 등록 불가 |
| P5 | 그룹 멤버가 아니면 피드 조회 불가 |
| P6 | 본인 지출만 수정·삭제(그룹장도 예외 없음) |
| P7 | 인식 실패해도 저장은 항상 성공 |
| P8 | 그룹 미소속이면 공유 select 자체가 안 보임 |
| P9 | 그룹 멤버가 아니면 정산 조회·계산 불가 |
| P10 | 그룹장은 새 그룹장 지정 없이 나갈 수 없음(그룹원이 혼자면 예외 — 그룹·지출 함께 삭제) |
| P11 | 본인이 아니면 개인 저금 조회·수정 불가 |
| P12 | 그룹 저금은 그룹 멤버만 조회, 등록한 사람만 수정 |

상태값 2가지(그룹장 이탈, 지출 인식 상태)와 서비스 정책(SP1~SP4)은 05-policy.md 참고.

## 7. 기술 스택 (SHY 스펙 기준, 2026-09-08 팀 결정)
| 영역 | 선택 |
|---|---|
| 프론트엔드 | React + TypeScript + Vite, Tailwind CSS |
| 백엔드 | 없음 — Supabase(BaaS)가 대체 |
| DB | Supabase(PostgreSQL), Supabase RLS로 05-policy.md 정책 구현 |
| 이미지 저장 | Supabase Storage |
| OCR | Naver Clova OCR 또는 Google Cloud Vision API, Supabase Edge Function 안에서만 키 사용 |
| 인증 | Supabase Auth(이메일/비밀번호) |
| 배포 | Vercel(프론트) + Supabase |

DB 스키마(SQL)·RLS 정책 전문, Edge Function 설계는 `모듈 1 SHY프로젝트 주제 세분화.md` "3. DB 스키마" 참고. 06-data.md는 이 스키마에 Saving(저금)을 더한 버전이다.
