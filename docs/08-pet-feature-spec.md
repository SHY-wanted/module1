# 06. 저금통 펫 키우기 — 화면·기능 명세

클로드 디자인(Claude Design)에서 만든 프로토타입을 기반으로 정리한 명세입니다. 프로토타입은 `.dc.html` 전용 포맷이라 VS Code에서 바로 실행되는 코드는 아니고, 이 문서를 참고해서 React/HTML 등 실제 코드로 구현하면 됩니다.

> **2026-09-15 갱신(종민 확인, §9 참고)**: 07-screens.md·06-data.md의 "구현 전 확인 필요 [?] 목록" 중 3개 항목(펫 소유 구조, 예산 개념, 주간 정산 배치 실행 방식)에 대해 종민이 방향을 정했다. 나머지 항목(진입 시점, XP·코인 수치, 예산 초과 처리, 정산 요일·시각·타임존, 하단 탭 진입점)은 여전히 미정이다 — 아래 §9 참고.

## 0. 전체 개념

지출을 기록하고 예산 안에서 절약할수록 펫이 성장하는 저금통 게이미피케이션 기능입니다. 초과 지출 시 "깨진 이미지" 같은 벌칙 대신, XP(경험치)를 덜 얻는 방식으로 부드럽게 동기부여합니다.

- 펫 종류(4종): 백호(tiger), 강아지(dog), 고양이(cat), 흑룡(dragon)
- 성장 단계(5단계): 알 → 유년기 → 청소년기 → 성체 → 전설
- 종별 5단계 이미지가 이미 준비되어 있음 (각 380px 폭 JPEG)
- 공통 데이터: `species`(펫 종류), `petName`(펫 이름), `stageIndex`(1~5, 현재 성장 단계), `xpProgress`(현재 단계 내 진행률 %)

## 1. 펫 선택 화면 (PetSelect)

최초 1회, 펫을 고르는 화면입니다.

- 4개 카드(2x2 그리드): 백호/강아지/고양이/흑룡, 각 카드에 유년기 단계 썸네일 이미지
- 카드 탭 → 선택 상태(테두리+그림자 강조, 체크 배지 표시)
- 선택 후 펫 이름 입력(선택 사항, 비우면 종별 기본 이름 사용: 백설/몽이/나비/칠흑)
- 하단 CTA 버튼: 선택 전엔 비활성(연보라), 선택 후 활성(그라데이션 보라)
- 저장 데이터: `species`, `petName` → **2026-09-15 종민 확인**: 개인 펫(사용자 1인당 1마리, §6 랭킹의 대상)과 그룹 펫(그룹당 1마리, 그룹원이 함께 키움)이 둘 다 존재하는 구조로 방향을 정했다. 펫 선택 화면(P1)은 개인 펫·그룹 펫 둘 다에 쓰이되, 그룹 펫은 최초 1회를 누가(그룹장? 아무나?) 언제 고르는지는 아직 미정 — §9-2 참고

## 2. 펫 상세·성장 화면 (PetDetail)

펫의 현재 상태를 보여주는 메인 화면입니다.

- 상단: 현재 단계의 펫 이미지 (원형, 살짝 위아래로 움직이는 애니메이션)
- 성장 트래커: 5단계를 가로로 나열, 현재 단계까지는 컬러+선명, 아직 도달 못한 단계는 회색조+반투명(잠금 표시)
- XP 진행 바: 현재 단계 내에서 다음 단계까지 진행률(%)
- 이번 달 예산 사용률(`budgetUsedPercent`, 0~140%) — 참고용 지표
- 필요 데이터: `species`, `petName`, `stageIndex`, `xpProgress`, `budgetUsedPercent`

## 3. 데일리 먹이주기 팝업 (PetFeedPopup) — 재미 요소 ①

- 노출 시점: 사용자가 지출을 하나라도 기록한 직후 (하루 1회만 트리거, 이미 오늘 먹이를 줬으면 팝업 자체를 띄우지 않음)
- 팝업 구성: 배경 딤 처리 + 중앙 카드
  - 먹이 주기 전: "OO(이)가 배고파해요" 문구 + "밥 주기" 버튼
  - 밥 주기 탭 → "냠냠, 잘 먹었어요!" 문구로 전환, `+xpGained XP 획득` 뱃지 표시, XP 바가 즉시 갱신됨
  - 확인 버튼으로 닫힘
- 필요 데이터/로직:
  - `lastFedDate` (마지막으로 먹이 준 날짜) — 오늘 날짜와 비교해서 팝업 노출 여부 결정
  - `xpGained` (1회 먹이주기당 지급 XP, 기본값 15 — 실제 값은 서버 정책으로 결정)
  - 지급 후 펫의 `xpProgress`, 필요 시 `stageIndex`를 갱신 (XP가 100%를 넘으면 다음 단계로 승급)

## 4. 주간 절약 리포트 (WeeklySavingsReward) — 재미 요소 ②

- 노출 시점: 매주 정산 시점(예: 매주 월요일 또는 주간 마감 시)에 지난 한 주의 예산 대비 지출을 계산해서 보여줌
- 화면 구성:
  - 이번 주 예산 / 실제 지출 / 절약액 비교 카드 (막대 그래프 포함)
  - 절약액을 "저금통 코인"으로 환산해서 지급 (`coinsEarned`) — 환산 비율은 아직 미정, 정책 필요 (예: 절약 1,000원당 1코인 등)
  - 코인 지급과 동시에 펫 XP도 함께 지급 (`xpGained`)
  - 누적 코인(`totalCoins`) 표시
  - "펫 보러가기" 버튼으로 PetDetail로 이동
- 필요 데이터: `weekRangeLabel`, `budgetAmount`, `spentAmount`, `coinsEarned`, `totalCoins`, `xpGained`
- 주의: 절약액이 음수(예산 초과)인 경우 이 리포트를 어떻게 처리할지는 별도 정책 필요 (0으로 표시하거나 리포트 자체를 생략하는 방식 추천) — **여전히 미정, §9-4 참고**
- **2026-09-15 종민 확인**: 이 앱엔 원래 "예산" 개념이 없었는데(2c 설정의 "예산 초과 시 알림"도 이 이유로 삭제된 전례 있음, 07-screens.md 2c 참고), `budgetAmount`의 출처를 **새 예산 설정 기능을 만들어 해결**하기로 정했다. 아래 §4-1(예산 설정 화면, BudgetSetting) 참고. **주의**: 2c의 "예산 초과 시 알림" 삭제 결정과 이번 결정이 서로 다른 문제(그때는 알림, 지금은 리포트)라 자동으로 되돌리는 건 아니지만, 예산 개념 자체가 다시 생기는 거라 2c 알림 행을 되살릴지는 팀이 별도로 정해야 한다

### 4-1. 예산 설정 화면 (BudgetSetting) — 신규, 2026-09-15 종민 확인으로 추가

- 진입: 설정(2c) 화면에 "주간 예산 설정" 행 추가 → 탭하면 이 화면으로 이동
- 구성: 이번 주 예산 표시 카드, 금액 직접 입력(+1만/+10만/+50만 빠른 증가 버튼, 초기화), "매주 같은 금액으로 자동 반복" 토글, "저장하기" 버튼
- 필요 데이터: `weeklyBudgetAmount` (주간 예산 금액), 자동 반복 여부
- 저장 위치: 아래 §8 `budgets` 테이블 참고
- 미정: 예산을 개인 단위로만 둘지, 그룹에도 별도 예산을 둘지는 정하지 않음(현재 명세는 개인 예산만 가정) — §9-2 참고

## 5. 나의 배지 (MyBadges) — 재미 요소 ③

- 마이페이지 → "나의 배지" 카드 탭 → 진입
- 5개 배지가 성장 단계와 1:1로 매칭됨 (알 배지, 유년기 배지, 청소년기 배지, 성체 배지, 전설 배지)
- `stageIndex` 이상 도달한 배지는 컬러+체크 표시, 아직인 배지는 회색조+자물쇠 아이콘
- 상단에 "획득한 배지 N/5" 진행 바
- 필요 데이터: `stageIndex` (이미 PetDetail과 공유되는 값이라 별도 저장 불필요, 계산만 하면 됨)

## 6. 그룹 저금통 랭킹 (GroupPetRanking) — 재미 요소 ④

- 그룹상세(GroupDetail) 화면 상단에 미니 랭킹 카드 추가: 이번 주 그룹 멤버들의 XP 획득량 순위 (1~2위 정도만 간단히 표시, 🥇🥈 아이콘)
- "전체 보기" 탭 → 그룹 전체 랭킹 화면(GroupPetRanking)으로 이동, 전체 멤버를 XP 순으로 정렬한 리스트 + 진행 바
- 순위 기준: **이번 주 획득한 펫 XP 총량** (지출 액수나 절약 액수를 직접 비교하는 게 아니라, XP로 환산된 값 기준 — 특정 멤버의 지출 내역이 과도하게 노출되지 않도록 하는 장치이기도 함)
- 화면 하단에 "지출을 줄이는 게 아니라 서로의 성장을 응원하는 용도"라는 안내 문구 포함 — 경쟁적/수치심 유발 요소가 되지 않도록 하는 문구
- 필요 데이터: 그룹 멤버별 `weeklyXp` (이번 주 누적 XP), `name`, 아바타 이니셜
- **2026-09-15 종민 확인**: 이 랭킹은 §1에서 정한 **개인 펫**의 XP를 비교하는 화면이다. 그룹 펫(그룹이 함께 키우는 1마리)은 이 랭킹과 별개로 존재하며, 그룹 펫이 정확히 어떻게 XP를 얻는지(멤버 개개인의 먹이주기·절약을 합산하는지, 그룹 단위로 별도 예산/정산을 두는지)는 아직 팀이 정하지 않았다 — §9-2 참고, 지어내지 않음

## 7. 마이페이지 변경 사항

기존 마이페이지에 다음 2개 카드가 추가됨:

- **저금통 코인 카드**: 펫 썸네일 + "저금통 코인" 라벨 + 누적 코인 수 (`totalCoins`)
- **나의 배지 카드**: 배지 아이콘 + "나의 배지" 라벨 + "N/5" 진행 상황 + MyBadges 화면으로 이동하는 링크

## 8. 백엔드(Supabase) 설계 시 참고사항

MVP 범위에서 최소로 필요한 테이블/필드 제안입니다 (실제 스키마는 팀 논의로 확정):

- `pets` 테이블: `user_id` **또는** `group_id` (2026-09-15 확인: 배타적 — 개인 펫 행은 `user_id`만, 그룹 펫 행은 `group_id`만 채움, 아래 §9-2 참고), `species`, `pet_name`, `stage_index`, `xp_progress`, `total_coins`
- `pet_feed_logs` 테이블 (또는 `pets.last_fed_date` 필드): 하루 1회 제한 체크용
- `budgets` 테이블(신규, 2026-09-15 확인): `user_id`, `weekly_amount`, `auto_repeat`(불리언) — §4-1 BudgetSetting 화면이 쓰는 값
- `weekly_settlements` 테이블: `user_id`, `week_start`, `budget_amount`(위 `budgets`에서 조회), `spent_amount`, `coins_earned`, `xp_gained` — **2026-09-15 확인**: 배치 실행은 Supabase Edge Function + cron 스케줄로 정했다. 단, 정확한 기준 요일·시각·타임존은 아직 미정(§9-4) — 배치가 실패하거나 늦게 도는 경우 처리(재시도·중복 실행 방지)도 아직 설계 안 됨
- XP → 단계 승급 로직: XP가 100%를 넘으면 `stage_index += 1`, `xp_progress`는 초과분으로 재설정 (5단계가 최대이므로 그 이상은 XP만 누적되고 단계는 고정)

**결정된 것**
1. **예산 개념**: 없던 "예산" 개념을 위해 §4-1 예산 설정(BudgetSetting) 화면을 새로 만들기로 함 — 개인 단위 주간 예산
2. **펫 소유 구조**: 개인 펫(1인당 1마리, 랭킹 대상) + 그룹 펫(그룹당 1마리, 그룹원이 함께 키움) — 개인 전용도 그룹 전용도 아닌 **둘 다 존재하는 구조**
3. **주간 정산 배치 실행 인프라**: Supabase Edge Function + cron으로 하기로 함 (pg_cron 등 다른 방식은 검토 안 함)

**여전히 [?]로 남은 것** (이 문서가 임의로 정하지 않음, 팀 확인 필요)
1. P1(펫 선택) 정확한 진입 시점 — 회원가입 직후 자동인지, 마이페이지에서 수동 진입인지
2. 그룹 펫이 정확히 어떻게 XP를 얻는지 — 멤버 개인 활동을 합산하는지, 그룹 전용 예산/정산을 따로 두는지 (§1, §6 참고) — **개인+그룹 구조를 정하며 새로 생긴 질문**
3. XP·코인 구체적 수치 — 먹이주기 1회당 XP(기본 제안 15), 절약액→코인 환산 비율, 주간 정산 XP 지급량
4. 주간 정산의 정확한 기준 요일·시각·타임존
5. 예산 초과(절약액 음수)일 때 처리 방식 — 0 표시 vs 리포트 생략
6. 하단 탭·내비게이션에 펫(PetDetail) 상시 진입점이 없음 — 현재는 마이페이지 카드로만 진입 가능
7. §4-1에서 만든 예산 개념이, 2c(설정)에서 "예산 초과 시 알림"을 예산 기능이 없어서 삭제했던 기존 결정(07-screens.md 2c, 2026-09-17)과 어떻게 맞물릴지 — 그 알림을 되살릴지는 별도 논의 필요
